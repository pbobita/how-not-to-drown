## How not to Drown – Manual Test Case Design Project

### Project Overview  
This project focuses on learning how to design efficient manual test cases through hands-on experimentation. The challenge begins by intentionally creating an overwhelming number of test cases based on assumptions and creativity — without written requirements. Then, using test design techniques, the goal is to refine this chaotic set into a clean, efficient, and maintainable test suite.

### Objectives  
- Practice writing manual test cases without formal requirements  
- Apply test design techniques (e.g. equivalence partitioning, boundary value analysis)  
- Learn to distinguish between redundant and essential test cases  
- Improve clarity and reproducibility in test documentation  
- Reflect on the difference between exploratory and structured test design

### What I Did  
- Created a **test case spreadsheet template** that allows others to execute tests without additional instructions  
- Wrote **30+ exploratory test cases** based on assumptions and edge-case thinking  
- Applied test design techniques to reduce and refine the test set into a **minimal, non-overlapping collection**  
- Documented the **system under test (SUT)** and test logic in a clear, structured format  
- Asked someone else to execute the efficient test cases to verify clarity and reproducibility  
- Reflected on the process and documented how test design techniques improved the outcome

### 📄 Files Included  
- `how_not_to_drown.xlsx` – contains all test documentation in separate sheets:
  - **Template** – the test case documentation template, designed to be clear and executable without extra instructions  
  - **Test Cases** – the initial exploratory test set with 30+ creative test cases based on assumptions and edge-case thinking  
  - **Test Cases – Refactor** – the refined test set using test design techniques, focused on efficiency and non-overlapping coverage  
- `README.md` – this file

### Key Learnings  
- Writing too many test cases without structure leads to duplication and confusion  
- Test design techniques help focus on what really matters  
- Clear documentation is essential — others should be able to run your tests without asking questions
